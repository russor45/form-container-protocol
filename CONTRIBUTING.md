# 🛠️ Contributing to the Form Container Protocol

Welcome! We're thrilled you're interested in contributing to the Form Container Protocol — a framework-agnostic, accessible, and agentic contract for form containers. This project aims to unify modal, side-panel, and inline form patterns across ecosystems. Whether you're here to refine the spec, improve reference implementations, or enhance documentation, your input is valued.

---

## 📦 Repository Structure

- `README.md` — Overview and goals
- `spec/` — Protocol definitions and appendices
- `docs/` — Extended documentation, mental models, migration guides
- `docs/HISTORY.md` — Versioned evolution of the protocol
- `src/examples/` — Reference implementations (e.g., ShadCN Vue)
- `tests/` — Protocol compliance tests

---

## 🚀 How to Contribute

### 1. Fork & Clone

```bash
git clone https://github.com/your-username/form-container-protocol.git
cd form-container-protocol
```

### 2. Create a Branch

```bash
git checkout -b feat/your-feature-name
```

Use semantic branch naming:
- `feat/` — New spec feature or implementation
- `fix/` — Bug fix or compliance correction
- `docs/` — Documentation updates
- `refactor/` — Non-breaking structural changes

### 3. Make Your Changes

- Follow spec formatting conventions (`spec/README.md`)
- Ensure accessibility contracts are preserved
- Update tests and examples if applicable

### 4. Commit Guidelines

Use conventional commits:

```bash
git commit -m "feat(protocol): add slot contract for trigger responder"
```

### 5. Push & Open a PR

```bash
git push origin feat/your-feature-name
```

Then open a Pull Request with:
- Clear description of changes
- Rationale and references (e.g., WCAG, ARIA, Radix)
- Any migration or compatibility notes

---

## ✅ Contribution Checklist

Before submitting a PR:

- [ ] Spec changes follow semantic structure
- [ ] Reference implementations are updated
- [ ] Accessibility and ARIA roles are validated
- [ ] Tests pass locally
- [ ] Documentation is updated (if needed)
